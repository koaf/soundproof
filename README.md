# SoundProof v0.3 — 音声納品チェック

音声をドラッグ＆ドロップして品質を検査し、気になる区間を **選択 → 原音と修正案を試聴 → 修正を適用 → 再検査** できる、アカウント不要の静的Webアプリです。

**GitHub Pagesで公開できます。** サーバーやデータベース、ビルド、アカウント登録、音声ファイルのアップロードは不要です。解析と区間修復の数値処理はC製WebAssembly + Web Worker、EQプレビュー・デコード・WAV書き出しはブラウザのWeb Audio APIとJavaScriptで動作します。GitHub Pagesからのアプリ本体ダウンロード以外に音声を外部送信する機能はありません。

## 今回追加した機能（v0.3）

- **問題箇所の一覧**：WASMで検出したクリック、50/60Hzハム、高域ノイズの候補を時刻順に一覧表示。候補を選ぶと波形上に選択範囲を表示。
- **波形から範囲を選択**：波形を左右にドラッグして任意の区間を指定。クリックは再生位置の移動。1回の修正は最大20秒。
- **区間をA/B試聴**：「元音」と「修正案」を選択区間だけ再生して比較（比較時は5バンドEQを通しません）。
- **WebAssemblyで部分修正**：
  - 50Hzノッチフィルター（50/100/150Hz。Q=25）
  - 60Hzノッチフィルター（60/120/180Hz。Q=25）
  - 8.5kHzローパス（高域ノイズ候補の軽減）
  - 短いクリック候補の5サンプル補間
  - 区間音量の減衰（最大-18dB）
  - 修正強度0〜100%、ノッチ／ローパス／減衰には約18msのフェードを付加
- **適用・再検査・直前1回取り消し**：編集はブラウザ内でデコードしたPCMの選択区間に適用。修正後のラウドネスやノイズ候補を再計測し、WAVに書き出せます。元ファイルは変更されません。

**ノイズ除去の成功を保証する機能ではありません。** ハム・高域ノイズはヒューリスティックに検出した「候補」です。音楽・声の成分を誤検出することがあり、フィルターが声や楽器の音色も変える場合があります。必ず試聴してください。クリック補間は一瞬の突出した候補向けで、長いクリッピング・歪みの修復ではありません。

## 従来からの機能

- 簡単チェック：LUFS、Sample Peak、True Peak近似、クリッピング、無音、ノイズ候補、位相の注意
- 詳細チェック：RMS、LRA、DCオフセット、L/Rレベル差、FFT帯域バランス、WAV元形式の情報
- 一括検査：最大20ファイル、ファイル単位の成否表示、個別詳細、一括CSV
- 5バンド・パラメトリックEQ：BiquadFilterによる試聴、EQカーブ表示、パラメーター変更
- WAV書き出し：48kHz / 16bit PCM WAV。部分修正とEQの両方を適用した音声を書き出せます
- 用途別判定目安：ボーカル、ナレーション、動画、汎用（正式な納品仕様ではありません）

## GitHub Pagesで公開する手順

1. GitHubで新しいリポジトリ（例：`SoundProof`）を作成します。
2. 配布ZIPを解凍し、**`index.html`、`app.js`、`soundproof.wasm` など中身をリポジトリのルートに配置**します。親フォルダごとアップロードしないでください。
3. **Settings → Pages → Build and deployment** で、**Deploy from a branch**、`main`、`/(root)` を選択します。
4. 保存後、`https://ユーザー名.github.io/SoundProof/` などからアクセスできます。

コンパイル済みの `soundproof.wasm` と `.nojekyll` が含まれます。外部CDN依存はありません。相対パスで読み込むため、プロジェクトページのサブパスでも動きます。

## ローカル開発

`file://` でHTMLを直接開くとWorkerの読み込みが制限されます。HTTPサーバーで起動してください。

```bash
cd SoundProof
python -m http.server 8080
```

`http://localhost:8080/` にアクセスします。

WebAssemblyを修正して再ビルドする場合はclang（wasm32対応）が必要です。

```bash
cd wasm
make
cd ..
node tests/smoke.mjs
node tests/noise.mjs
node tests/repair.mjs
```

オプション：Chromium + Python Playwrightで画面操作をテストできます。

```bash
python tests/browser_test.py
```

`tests/browser_test.py` は制限付き環境でも動かせるようWorkerをインラインで模擬していますが、WebAssembly自体は実物を使います。`tests/browser_repair_test.py` は実WorkerをHTTP経由で確認する追加テストで、localhostへのアクセスが可能な環境で実行します。

## 技術仕様・注意点

- 解析は入力音声をブラウザで**48kHzのPCMへデコード／リサンプリング**した後に実行。WAV形式のみ元ファイルのビット深度とレートをヘッダーから表示。他形式の対応は各ブラウザのデコーダーに依存します。
- 1ファイル130MB以下、30分以下、モノラル/ステレオ。長時間・大量のPCMはブラウザのメモリを多く消費します。編集中はデコードしたPCM全体を保持し、取り消し用には最後に編集した区間の元サンプルだけを保持します。
- 区間修正は**一度に20秒まで**。修正後の波形・解析値は更新されます。修正の取り消しは直前の1操作分だけで、ブラウザ更新時には消えます。
- **別ファイルを開くと作業中の部分修正は破棄されます。** 保存する際はその前にWAVを書き出してください。一括検査の表は元ファイルの測定結果を示します。
- EQは音声の再生と書き出しに反映。**EQのパラメーター操作だけでは検査値は更新されません**（出力後に再読み込みして検査してください）。
- 部分修正とEQの効果によってピークが上がる場合は、16bit PCM WAVへの書き出し時にクリッピングする可能性があります。出力ファイルを必ず再検査してください。
- LUFSはBS.1770系の簡易ゲーティング測定、True Peakは4倍補間の近似値です。**認証済みの規格適合測定器ではなく、厳密な納品基準を保証しません。**
- ノイズ検査は48kHz PCMの低音量区間を最大32か所抽出するヒューリスティックです。ハムは50/60Hzに近い狭帯域の強い成分、高域ノイズは広帯域エネルギーを候補として表示します。ノイズがないと断言するものではありません。
- クリッピングは上限付近に張り付いたサンプルを検出する簡易方式で、劣化したMP3の歪みを自動で診断するものではありません。
- ファイルや結果はブラウザ内だけにあります。**アカウント、クラウド保存、履歴同期機能はありません。**
